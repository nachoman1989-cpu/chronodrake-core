## 1. Architectural Decisions

### Decision: Modular Scanner Architecture

- **Context:** Need to support multiple technology stacks (Rust, Node.js, Tauri)
- **Decision:** Each technology has its own scanner module (`scanner/rust.rs`, `scanner/node.rs`, `scanner/tauri.rs`)
- **Tradeoff:** More code upfront, but easier to extend with new technologies
- **Status:** ✅ Implemented

### Decision: SQLite for Persistence

- **Context:** Need offline-first, deterministic, local storage
- **Decision:** Use SQLite via `rusqlite` — no server, no cloud, no dependencies
- **Tradeoff:** Not suitable for distributed/cloud scenarios without additional tooling
- **Status:** ✅ Implemented

### Decision: Schema Versioning with Migrations

- **Context:** Database schema evolves across versions
- **Decision:** Implement `schema_version` table + sequential migration engine
- **Tradeoff:** Adds complexity but ensures backward compatibility
- **Status:** ✅ Implemented

### Decision: Knowledge Graph in SQLite

- **Context:** Need relationship tracking between modules, dependencies, and features
- **Decision:** Store graph edges directly in SQLite tables (no separate graph DB)
- **Tradeoff:** Less performant for complex graph queries, but simpler infrastructure
- **Status:** ✅ Implemented

### Decision: AI Context Engine (v0.6)

- **Context:** Need to provide full project context to any AI model
- **Decision:** Generate deterministic markdown files in `/ai-context/` directory
- **Tradeoff:** Static files vs. dynamic API — no real-time updates, but zero infrastructure
- **Status:** ✅ Implemented

## 2. Why These Decisions Were Made

- **Offline-first:** All features must work without internet access
- **Deterministic:** Same input always produces same output — no AI APIs, no randomness
- **Local-first:** No cloud, no telemetry, no external dependencies
- **Extensible:** New scanners, analyzers, and generators can be added without modifying existing code
- **Typed errors:** Using `thiserror` for all error types — no `anyhow` in library code
- **Strong typing:** `serde` everywhere for serialization

## 3. Security Decisions

- **No AI APIs:** All analysis is local and deterministic
- **No telemetry:** No data leaves the machine
- **No cloud:** No external service dependencies
- **SHA-256 integrity:** Cache entries are verified with content hashing
- **SQLite file permissions:** Database respects filesystem permissions

## 4. Rejected Alternatives

| Alternative | Reason for Rejection |
|-------------|---------------------|
| PostgreSQL | Requires server, not offline-first |
| MongoDB | Heavy dependency, not deterministic |
| Neo4j (graph DB) | Overkill for current scale, adds complexity |
| Redis cache | External dependency, not local-first |
| Cloud sync | Violates offline-first principle |
| AI embeddings | Requires API calls, not deterministic |
| Vector database | Requires AI pipeline, violates local-first |
| YAML config | TOML is more readable and standard for Rust |
| JSON schema | TOML is more human-friendly for config |
